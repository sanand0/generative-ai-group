Maya: Right. Instead of stuffing a giant prompt with every tool description, the agent writes code against a typed interface and runs it safely. That means the code becomes a compact plan.

Alex: Alok really leaned into that idea too. He said Claude workflows are “absolutely amazing,” and later explained that if a task can be described as a graph or conditional flow, you can turn it into a workflow file with templated prompts and branches.
Maya: That’s the non-obvious takeaway: the agent doesn’t always need “more intelligence.” Sometimes it needs better structure. A workflow can make the model behave more like a reliable system than a freestyle assistant.
Alex: Alok also shared a practical pattern that worked for him: adding a content index with short descriptions of when to use skills.
Maya: That’s huge for the “too many skills, not enough focus” problem. Abhishek called it the “md as router principle,” and Nipun described a high-level markdown doc that orchestrates all the skills, so you only load the relevant ones when needed.
Alex: So if you’re building an agent plugin, the practical idea is: make one small router document, then lazy-load the heavy bits only when the router says so.
Maya: And don’t miss the caveat Alok gave: this works best when each agent is stateless, or at least not relying on shared context. That’s a nice reminder that elegance and reliability often come from reducing memory, not expanding it.
