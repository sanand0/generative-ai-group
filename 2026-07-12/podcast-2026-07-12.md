Alex: Let’s start with something that came up again and again: harness engineering.
Maya: Right, “harness” just means the wrapper or setup around the model, like the tools, prompts, checks, and workflow it runs inside.
Alex: Dev shared Drew Breunig’s post, The Cost of Overfitting the Harness, and also linked Lilian Weng’s piece on harness engineering.
Maya: And the core idea is really important: models may get better at using their own favorite tool shapes, but that can make them worse at working with other tools.
Alex: Dev put it nicely in the thread: if reinforcement learning happens inside a harness, malformed tool calls can still get the job done and still get rewarded.
Maya: So the model may learn the “vibe” of the tool instead of the real behavior. That’s great when it works, but fragile when you move to a different app or a different schema.
Alex: Exactly. And that “chicken and egg” problem came up too. If your model is weak, the harness has to be forgiving.
Maya: But if the harness is too forgiving, the model never gets punished for sloppy behavior.
Alex: That matters for anyone building agents. A polished benchmark can hide real-world failure.
Maya: Practical takeaway: test your agent in more than one harness. Don’t just ask, “Does it work in my ideal setup?”
Alex: Ask, “Does it still work if the tool names change, the schema shifts, or the UI moves a little?”
Maya: That’s the difference between a demo and something you can trust.

Alex: The other big theme here was agent reliability and security.
Maya: Huge theme. Chinmay Shah asked about least-privilege IAM for Slack, Drive, Jira, and other tools.
Alex: And the responses were strong: Manoj Bajaj said to put guardrails at the OAuth scope level, and Dev pointed to sandboxing with Deno and Cloudflare Workers.
Maya: Pratik Desai also gave the blunt version: “You can’t trust a stochastic process” to follow instructions, no matter how good it is.
Alex: That’s the key thing non-technical listeners should know. AI agents are not obedient employees.
Maya: They’re probabilistic systems. They can misunderstand, improvise, and occasionally do something very confident and very wrong.
Alex: Which is why tools like Composio, Nango, and MCP servers matter so much.
Maya: Speaking of MCP, Mohamed Yasser shared Sarvam’s MCP Server, where coding agents can discover and use Sarvam through one config.
Alex: That’s a good example of the ecosystem maturing. The agent doesn’t need a custom one-off integration every time.
Maya: But the safety side has to mature too. Dev shared Claw Patrol, which sits between the agent and the network and injects credentials the agent never sees.
Alex: That’s a smart pattern: hide secrets, keep policy in code, and limit blast radius.
Maya: If you’re building with agents, the non-obvious takeaway is this: make permissions boring.
Alex: [laughs] Boring is good when the thing can click, send, buy, or delete.
